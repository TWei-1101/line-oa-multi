# Family LINE bridge — staged, disabled by default

Local implementation only. No deployment, credential provision, real model/LINE call or activation is authorized by this document. Existing aiassistant/global Mac settings and the Mac adapter stay unchanged.

## Authenticated staging and bot identity

Use the Ingress/CSRF-protected GET/PUT /api/accounts/family/openclaw settings and the account dialog. Stage with enabled:false. The optional endpoint is either exactly {mode:inherit}, or a complete override: mode, url, token, agent, timeout_seconds, protocol. A blank override token in the UI omits the token and preserves only that same account override's credential; it does not inherit the global token. Unchecking the override explicitly resets to inherit, which cannot enable family. Tokens are never returned in status or errors.

Set expected_destination to the independently verified Messaging API bot U… identifier through this authenticated settings path. A signed packet's first-learned destination alone is NOT trusted expected identity. Enablement requires BOTH this expected value and the matching Channel-Secret-signed webhook binding, family-text-v1, fixed family-line agent, self-mention-group-text admission and a nonempty group route allowlist. Before binding, receive a synthetic/authorized signed verification packet through the normal webhook transport while the bridge stays disabled. Legacy accounts retain first-binding onboarding. Secret/channel changes clear the learned binding: disable family, reverify binding, then explicitly enable. OA Manager chatId and Messaging API groupId are different identifiers: never infer their mapping by equality.

Only a structurally valid self mention of that destination in allowlisted group text enters the family queue. Optional isSelf/userId forms are preserved. Malformed metadata, surrogate/truncated spans, excessive count/bytes and mismatched expected destinations suppress family admission without removing otherwise valid webhook events from the HA inbox.

## Immutable jobs and maintenance

Job creation, model credential revision, optional image credential revision, concrete OA recipient and version-1 snapshot commit in one SQLite transaction. The snapshot pins endpoint/protocol/agent/timeout/admission/session policy and actual session value; family also pins expected bot identity. Rotations apply only to new jobs. Private revision values are never exposed in status. The worker validates the complete snapshot and revisions before media, upstream generation or ready sends. Each actual MessageSender send compares the alias against the original recipient and captures the primitive chatId before awaiting validation. Supported alias mutation HTTP handlers guard only outstanding jobs for the affected account+alias. There is no arbitrary-target send HTTP API.

POST /api/openclaw/worker with {action:pause} prevents fresh timer work, clears the timer and awaits active generation/media/sends; it does not abort or rewrite snapshots. {action:resume} explicitly resumes. The dialog provides both controls. For emergency intake disable, PUT exactly {enabled:false} to /api/accounts/<account>/openclaw. This scoped safety-only write remains available during active work, after alias disappearance, or when unrelated account bindings drift; it preserves all routes, endpoint/credential settings and immutable job rows. Adding any other patch field, enabling, or changing routing/identity still uses strict full validation. Pause is in-process, not a persistent service maintenance lock: stop/restart/deployment remains a separate operator boundary.

## Migration: fail-closed controlled hold, not automatic pinning

No automatic legacy pinning is implemented or claimed. On load, every nonterminal unsnapshotted/incomplete row is durably held as unknown / SNAPSHOT_INVALID_REVIEW_REQUIRED before any media or upstream effect. Family rows NEVER acquire global Mac defaults. Interrupted/repeated loads retain IDs, recipient, outputs, next part and dedup rows. Terminal submitted/ignored rows are retained, not replayed. Valid generating restarts need explicit review; valid sending restarts are uncertain and never automatically resent. Review actions preserve snapshot/revision/recipient identity.

Maintenance procedure: disable intake, pause/drain, inspect retained job/status evidence and take a consistent protected backup. For unsnapshotted jobs, keep the controlled hold unless an independently reviewed offline migration can prove unchanged historic endpoint, credential, session/admission policy AND the user-approved recipient. Current code does not provide a speculative pin/retry escape hatch: retrying an invalid snapshot simply holds it again. Explicit skip is available if the operator decides not to execute retained work. Do not rewrite SQL snapshots, substitute current credentials, discard uncertain rows, restore a whole historical DB, or infer missing mapping to manufacture a migration. Evidence-based pinning, if wanted later, needs a separately reviewed migration tool and authorization.

## Dedicated adapter boundary

Only POST /v1/responses JSON {version,event_id,group_id,text} is accepted. Fixed account family and model/agent family-line; group session routing is derived server-side. Headers/body are constructed afresh; caller routing headers, extra fields, media/tools, malformed UTF-8/JSON and command-like input (including leading mentions) reject. Plain URL text is inert input, not fetched as a URL. Lexical command filtering is conservative mitigation, NOT proof of owner-command isolation.

Use the dedicated family-bridge script, never the Mac adapter. Server-side environment supports FAMILY_BRIDGE_TOKEN, FAMILY_BRIDGE_GROUPS, FAMILY_BRIDGE_LEDGER and optional FAMILY_BRIDGE_PORT, FAMILY_UPSTREAM, FAMILY_UPSTREAM_TOKEN. Upstream is restricted to an HTTP loopback /v1/responses endpoint; Gateway bearer stays on that host. Provisioning these real values is NOT part of local work. Request body 32KiB, upstream response 64KiB, fatal UTF-8 decoding, 15s body lifetime, 30s upstream timeout, authenticated per-IP 60/minute limit and bounded concurrency apply. Only bounded completed assistant output_text is accepted.

The durable fixed-account/event ledger binds a canonical payload hash. Intent commits before dispatch; completion before reply. Identical completed retries return exactly {text}, including HTTP retries consumed by the HA parser. Changed payload conflicts. In-flight/crashed/uncertain intent stays held, not automatically rerun. Storage failures stop requests. Per-group serialization and global maximum eight active dispatches apply. No exactly-once LINE delivery claim; uncertain sends require human review. Generic upstream 429/503 is NOT proof of before-dispatch safety; HA family retries require adapter-owned before-agent evidence, never inferred from HTTP status alone.

## Executable startup / downgrade interlock

npm start invokes dist/scripts/controlled-start.js, which preflights the actual DATA_DIR/multi/openclaw.sqlite before spawning multi-server. Runtime and wrapper share src/data-paths.ts for both the multi root and SQLite filename; DATA_DIR uses the runtime default /data when unset or empty. Unknown/malformed snapshots, malformed JSON and column/body state disagreement fail closed. Forward startup permits unsnapshotted rows only so the new worker can place them in controlled holds.

Before an older/non-family-aware candidate is started, run npm run family-downgrade-preflight -- /data/multi/openclaw.sqlite (without --family-aware). It blocks family configuration, any nonterminal family row even if disabled/unsnapshotted, and incompatible versioned work. --family-aware is solely a declared candidate capability. This is an executable repository-controlled release boundary, NOT protection from an operator manually bypassing the wrapper or an old binary self-protection mechanism. A safe forward fix is preferred over transparent in-place downgrade.

## Still-required activation gates

Verified TLS trust or authenticated loopback-ended tunnel; dedicated bridge credential provision/transfer; exact user-approved group→OA mapping and test window; verified HA source/build/Supervisor maintenance path; and version-matched .241 runtime tools/context/native/plugin/owner-command isolation evidence. Shared group sessions expose admitted members to the same conversation context. If shared Gateway owner-command/context isolation is not provable, keep disabled and use a separate restricted Gateway/OS principal; agent selection is not a security tenant boundary. No production-readiness or activation approval is implied. DOM/API tests are meaningful interaction coverage, not visual browser verification.
